# ART SEOUL · 아트서울

기업·병원·호텔·매장을 위한 작품 렌탈과 공간 아트컨설팅 웹사이트입니다. React 19·TypeScript·Vite 6 프런트엔드와 Express·SQLite 상담 API를 함께 실행합니다. 한국어를 기본으로 구성하며, 실제 접수 없이 완료만 표시하던 기존 갤러리 시연 폼을 서버 저장 흐름으로 교체했습니다.

## 실행

Node.js **24**를 사용합니다. 버전 기준은 `.nvmrc`에 있습니다. 패키지 관리자는 npm이며 `package-lock.json`을 사용합니다.

```sh
npm start
```

잠금 파일에 맞춰 의존성을 설치하고 개발 서버를 엽니다. 이미 설치했다면 `npm run dev`를 사용하세요. 개발 서버, 빌드 미리보기, 운영 서버는 모두 **3000번 포트**를 사용합니다. 기존 서버를 종료한 뒤 다른 실행 모드로 전환하세요. 포트가 사용 중일 때 다른 포트로 자동 변경하지 않습니다.

- 개발: `npm run dev`
- 빌드: `npm run build`
- 빌드 미리보기: `npm run preview`
- 빌드와 API 운영: `npm run serve`

개발·미리보기에서는 Vite 미들웨어가 API를 연결합니다. 운영에서는 `server/index.ts`가 API와 `dist/` 파일, 상세 경로의 SPA 진입점을 제공합니다. `dist/`만 정적 호스팅하면 상담 API는 동작하지 않습니다.

## 구현된 화면과 기능

주 메뉴는 **작품 찾기 · 아트 렌탈 · 공간 컨설팅 · 프로젝트 · 작가 · 아트서울**의 6개로 구성합니다. 홈(`/`)에서 공간 유형과 서비스로 진입할 수 있습니다.

| 영역        | 경로와 기능                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| 작품 찾기   | `/artworks`, `/artworks/:slug` — 검색·필터 URL, 작품 상세, 치수를 활용한 참고용 2D 미리보기          |
| 관심 작품   | `/selection` — 여러 작품 저장·삭제, 선택한 작품을 상담에 전달                                        |
| 아트 렌탈   | `/rental` — 진행 과정, 업종별 안내, 견적 비용 구성, 설치 조건                                        |
| 공간 컨설팅 | `/consulting` — 프로젝트 과정, 산출물과 업무 범위                                                    |
| 프로젝트    | `/projects`, `/projects/:slug` — 업종별 공간 제안 예시와 상세                                        |
| 작가        | `/artists`, `/artists/:slug` — 작가와 작품 연결                                                      |
| 아트서울    | `/about` — 서비스 소개와 상담 진입                                                                   |
| 고객 안내   | `/support/faq`, `/privacy`, `/terms`, `/rental/terms`                                                |
| 상담        | `/inquiry`, `/inquiry/complete` — 입력 검증, 선택 작품·서비스·공간 정보, 실제 서버 저장 후 접수 번호 |
| 운영자      | `/admin/inquiries` — 인증 후 최근 상담 목록, 단계 필터, 단계·메모 수정                               |

관심 작품은 브라우저 로컬 저장소에 작품 식별값만 저장합니다. 다른 기기와 동기화되지 않으며 작품 예약을 확정하지 않습니다. 페이지별 제목·설명은 클라이언트에서 갱신하고, 상담·관심 작품·운영자 화면에는 `noindex`를 적용합니다.

현재 카탈로그와 공간 콘텐츠에는 **예시 데이터**가 포함되어 있습니다. 검증되지 않은 작가 이력·실제 고객 사례·렌탈 가격·재고를 실제 사업 정보로 표시하지 않습니다. 공개 작품의 월 렌탈료와 가용성은 확인이 필요한 상태이며, 2D 미리보기는 현장 실측이나 3D·AR을 대체하지 않습니다.

## 상담 접수 설정

공개 접수는 기본적으로 비활성화됩니다. `.env.example`을 `.env`로 복사한 뒤 운영자가 확정한 값을 입력하고 서버를 다시 시작하세요. 다음 조건을 모두 충족해야 활성화됩니다.

| 변수                      | 설정                                                         |
| ------------------------- | ------------------------------------------------------------ |
| `INQUIRY_ENABLED`         | 접수를 시작할 때만 `true`                                    |
| `INQUIRY_OPERATOR`        | 실제 상담 정보 운영자명                                      |
| `INQUIRY_PRIVACY_CONTACT` | 실제 개인정보 문의 이메일                                    |
| `INQUIRY_RETENTION_DAYS`  | 확정한 보관 일수, 1~3650의 정수                              |
| `ADMIN_TOKEN`             | 운영자만 사용하는 32자 이상의 무작위 비밀값                  |
| `INQUIRY_DATABASE_PATH`   | SQLite 경로. 기본값 `.data/inquiries.sqlite`                 |
| `PUBLIC_ORIGIN`           | 운영 HTTPS 사이트의 정확한 origin. 경로 없이 설정            |
| `TRUSTED_PROXY_IPS`       | 선택 사항. 실제 역방향 프록시의 IPv4/IPv6 주소를 쉼표로 구분 |

`ADMIN_TOKEN`은 서버 환경변수로만 관리하세요. **`VITE_*` 변수, 소스, 커밋, 고객에게 보내는 URL에 넣지 않습니다.** 실제 `.env`와 `.data/`는 Git에서 제외됩니다. 운영자 화면은 토큰을 페이지 메모리에만 보관하므로 새로고침하면 다시 인증해야 합니다.

`TRUSTED_PROXY_IPS`를 비우면 전달 헤더를 신뢰하지 않습니다. CIDR·와일드카드·전체 신뢰 설정은 허용하지 않습니다. 지정한 프록시가 실제 클라이언트 주소로 전달 헤더를 설정하는지 확인하세요. `PUBLIC_ORIGIN`은 HTTPS 프록시 뒤에서도 고객의 브라우저 origin과 일치해야 합니다.

상담은 서버의 SQLite에 실제 저장되며 중복 접수 키, 서버 입력 검증, 요청 수 제한을 적용합니다. **이메일 자동 발송·CRM 연동·담당자 알림은 구현하지 않았습니다.** 운영자는 상담 관리 화면에서 접수 내용을 확인해야 합니다. 상담 접수는 작품 예약·견적 승인·계약 체결이 아닙니다.

## 운영 배포

```sh
npm ci --include=dev
npm run build
NODE_ENV=production npm run serve
```

프로세스 관리 도구가 프로젝트 루트에서 운영 서버를 실행하도록 설정하세요. 저장소 변경이나 빌드만으로 호스팅이 자동 배포되지는 않습니다.

운영 환경에는 다음 구성이 필요합니다.

- HTTPS 역방향 프록시와 `PUBLIC_ORIGIN` 설정
- 앱 재배포·재시작에도 유지되는 SQLite 영구 볼륨과 접근 제한
- SQLite 데이터베이스와 WAL 상태를 고려한 일관된 백업·복원 절차
- 관리자 토큰의 안전한 보관과 교체 절차
- 개인정보 보관기간에 맞춘 원본·백업의 삭제 운영

데이터베이스를 `public/` 또는 `dist/` 아래에 두지 마세요. 서버는 이를 거부합니다. 보관 만료된 상담은 서버 시작, 정기 정리, 관련 API 접근 시 정리합니다. 백업의 보관·삭제는 운영자가 별도로 관리해야 합니다.

현재 저장소와 요청 수 제한은 단일 서버 운영을 기준으로 합니다. 여러 인스턴스 운영에는 데이터베이스·제한 상태 공유 설계가 추가로 필요합니다. 출시 전 확인 항목은 [운영 출시 체크리스트](docs/launch-checklist.md)를 참고하세요.

## 검증

```sh
npm run format
npm run lint
npm run format:check
npm run typecheck
npm test
npm run build
```

테스트는 문의 저장·중복 처리·입력 검증·인증·보관기간·요청 제한·신뢰 프록시 처리를 확인합니다. GitHub Actions는 main 대상 PR과 main push에서 린트·포맷·타입·API 테스트·빌드를 실행합니다. 브라우저에서는 모바일 메뉴, 필터·뒤로가기, 관심 작품, 접수 오류·완료와 운영자 화면을 함께 확인하세요.

## 코드 구조

```text
src/
  catalog.ts           작품·작가 예시 데이터
  domain.ts            작품·작가 모델
  content/services.ts  공간 유형·제안 예시·FAQ
  pages/               공개·상담·운영자 화면
  components/SiteLayout.tsx
  state/               관심 작품 상태와 로컬 저장
shared/inquiry.ts      클라이언트·서버 공유 입력 모델과 검증
server/
  config.ts            접수 활성화·운영 환경 설정
  app.ts               상담·운영자 API
  store.ts             SQLite 저장·보관기간 정리
  index.ts             운영 서버 진입점
tests/                API·저장 동작 테스트
```

작품 식별값을 변경하거나 추가할 때는 `src/catalog.ts`와 `shared/inquiry.ts`의 허용 목록을 함께 갱신하세요. 코드와 포맷 규칙, 작업 브랜치 및 main 반영 절차는 [AGENTS.md](AGENTS.md)를 따릅니다.

## 후속 구현 범위

견적서 발행·버전 관리, 계약·전자서명, 실제 작품 가용 일정과 중복 예약 방지, 설치·회수 업무 관리, 결제·정산, 고객 포털·다지점 권한, CMS, 실제 사진 업로드와 AR은 아직 구현하지 않았습니다. 현재 운영자 화면은 상담 관리에 한정됩니다.

초기 갤러리 UI의 원본은 [Google AI Studio 프로젝트](https://aistudio.google.com/apps/b917222e-a6ac-419e-93cd-890b49a347ae)입니다. 이 앱은 Gemini API를 호출하지 않으며 실행에 Gemini API 키가 필요하지 않습니다.
