- 범위: 정보 구조, 콘텐츠 위계, 디자인 시스템의 단서, 사용자 흐름, 서울아트 적용 방향

## 1. 분석 방법과 확인 범위

공식 홈페이지의 공개 HTML, 검색 도구가 추출한 본문, 홈페이지가 참조하는 CSS를 확인했다. 서울아트는 `src/App.tsx`, `src/data.ts`, 컴포넌트, 스타일 및 기존 실행 검증 결과를 기준으로 비교했다.

브라우저 렌더링을 시도했으나 `ERR_CERT_AUTHORITY_INVALID` 오류로 화면을 확인하지 못했다. 따라서 픽셀 단위 배치, 실제 적용 폰트, 고정 헤더, 메뉴 펼침 방식, 호버 효과, 슬라이더 자동 재생, 모바일 터치 동작은 검증하지 않았다. 아래에서 **확인**, **해석**, **제안**을 구분한다. CSS에 존재하는 규칙이 특정 화면에 실제 적용된다는 보장은 없다.

이 문서는 분석 자료다. 홈페이지 소스, 이미지, 문구를 복제하거나 서울아트 화면을 변경하지 않았다.

## 2. 핵심 결론

**해석:** 벤치마킹의 핵심은 개별 작품 카드의 모양보다, 전시를 입구로 삼아 작가의 활동과 갤러리의 문화적 맥락으로 탐색을 확장하는 편집 구조에 있다.

서울아트에 적용할 때는 다음 세 가지를 우선하는 편이 좋다.

1. 첫 화면에서 현재 전시의 정체성과 관람 정보를 빠르게 이해하게 한다.
2. 이미지와 짧은 정보의 반복 규칙을 통일해 콘텐츠를 훑기 쉽게 한다.
3. 실제 운영 가능한 전시·작가·방문·문의 경로를 완성한 뒤 콘텐츠 종류를 확장한다.

## 3. 원본에서 확인한 구조

**확인:** 메인 본문은 대표 전시, 예정 전시, 외부 미술관 전시, 언론 소개, 판화, 행사, 출판물, 팟캐스트, 이메일 구독, 지점 안내로 이어진다. 전시 정보는 작가·장소·기간을 함께 제공하고, 콘텐츠 종류에 따라 상세 탐색이나 청취·구독 행동으로 연결한다. 공개 이미지 주소에는 Sanity CDN이 사용된다.

## 4. 콘텐츠와 사용자 흐름 분석

### 4.1 전시를 출발점으로 삼는 구성

**해석:** 방문자는 작품의 의미를 모두 읽기 전에 무엇이 열리고 있는지, 어디에서 볼 수 있는지, 더 알아볼 대상이 무엇인지 파악할 수 있다. 날짜와 장소는 장식 문구보다 실질적인 탐색 정보를 제공한다.

**서울아트 제안:** 대표 전시 영역에는 전시명, 작가명, 기간, 장소, 상세 링크를 우선 배치한다. 장문의 큐레이터 노트는 상세 영역으로 옮겨 첫 화면의 판단 부담을 줄인다.

### 4.2 갤러리 밖의 활동으로 신뢰를 쌓는 구성

**해석:** 소속 작가가 외부 기관에서 활동하는 맥락과 편집 콘텐츠는 갤러리를 지속적으로 방문할 이유를 만든다. 다만 콘텐츠 수가 많아지면 게시 날짜와 종료 상태를 관리하는 운영 부담도 커진다.

**서울아트 제안:** 실재하고 확인 가능한 전시 이력이나 보도 자료가 있을 때만 별도 섹션을 만든다. 카드 수를 채우기 위해 임의의 이력이나 외부 기관 정보를 만들지 않는다.

### 4.3 행동 목적을 구분하는 링크

**서울아트 제안:** 전시에는 ‘전시 자세히 보기’, 작품에는 ‘작품 상세’, 방문 안내에는 ‘방문 정보’, 문의에는 ‘작품 문의’처럼 목적이 분명한 문구를 사용한다. 첫 화면에 여러 문의 버튼을 반복하기보다 탐색 후 자연스럽게 문의로 이어지게 한다.

## 5. 시각 디자인에 적용할 원칙

아래는 측정한 원본 치수가 아니라 **서울아트를 위한 설계 제안**이다.

| 항목 | 제안 | 기대 효과 |
| --- | --- | --- |
| 배경과 색 | 밝은 기본 배경, 어두운 본문, 절제된 구분선 | 작품 이미지에 시선 집중 |
| 타이포그래피 | 한글 가독성을 갖춘 산세리프 중심, 제한된 굵기 | 작은 정보도 읽기 쉽게 유지 |
| 제목 위계 | 섹션명·전시명·부가정보를 크기와 굵기로 구분 | 긴 페이지를 빠르게 탐색 |
| 여백 | 공통 좌우 여백과 섹션 간격 체계 사용 | 섹션별 인상 일관성 확보 |
| 이미지 | 전시 전경과 개별 작품에 서로 다른 표시 규칙 적용 | 공간감과 작품 전체 형태 보존 |
| 카드 | 과도한 테두리·그림자보다 이미지와 캡션 중심 | 콘텐츠 사이의 시각적 경쟁 감소 |
| 버튼 | 주요 행동만 강조하고 상세 탐색은 간결한 링크로 처리 | 클릭 우선순위 명확화 |

### 이미지 편집 기준

- 전시 전경은 주변 공간을 이해할 수 있는 사진을 사용한다.
- 작품 상세 이미지는 원본 비율을 우선하고, 중요한 부분을 임의로 자르지 않는다.
- 목록에서 썸네일 비율을 통일하더라도 상세 화면에서는 작품 전체를 보여준다.
- 이미지마다 작가·작품명에 맞는 대체 텍스트와 필요한 크레딧을 제공한다.
- 해상도별 이미지, 명시적 크기, 아래쪽 이미지의 지연 로딩을 고려한다.

### 모바일 설계 기준

원본의 모바일 화면 동작은 미확인이다. 서울아트는 모바일에서 한 열 중심으로 읽히게 하고, 전시명·기간·장소를 이미지 밖에서도 확인할 수 있게 구성하는 것을 권장한다. 탐색과 문의 기능이 호버에 의존해서는 안 된다. 언어 전환, 메뉴, 닫기 버튼은 터치와 키보드로 모두 사용할 수 있어야 한다.

## 6. 현재 서울아트와의 비교

| 관점 | 현재 서울아트에서 확인한 상태 | 권장 방향 |
| --- | --- | --- |
| 메인 구조 | 전시 → 작품 → 작가 → 가상 뷰잉룸 → 안내 | 전시와 방문 정보를 우선하고 뷰잉룸의 노출 비중 조정 |
| 첫 화면 설명 | 전시 데이터에 긴 큐레이터 설명 포함 | 요약과 상세 설명 분리 |
| 시각 요소 | 작은 대문자 정보, 세리프 제목, 그림자와 테두리 등 사용 | 한글 기준 정보 크기와 장식 밀도 정리 |
| 콘텐츠 이동 | 메인 내부 스크롤과 모달 중심 | 콘텐츠가 늘면 전시·작가 상세 주소 마련 |
| 문의 | 브라우저에서 임시 번호를 생성하는 시연용 폼 | 실제 저장·발송이 확인되는 접수 경로 구현 |
| 소셜 | 실제 계정 대신 `#` 링크 사용 | 운영 계정 연결 또는 링크 제거 |
| 헤더 문의 | `inquiry` 섹션으로 이동하는 코드가 있으나 해당 섹션 없음 | 실제 문의 경로나 갤러리 안내로 연결 |
| 전시 상태 | 전시 기간 데이터가 정적으로 입력됨 | 날짜에 따른 현재·예정·종료 상태 관리 |

특히 문의 접수와 헤더의 끊어진 연결은 화면 분위기보다 먼저 해결할 사항이다. 분석 시점에 샘플 전시의 종료일은 이미 지난 상태이므로, 실제 운영용 일정과 표시 문구도 확인해야 한다.

## 7. 서울아트 메인 구성 제안

원본의 모든 콘텐츠 종류를 도입하기보다, 서울아트가 실제로 운영할 수 있는 정보량에 맞춘다.

```text
헤더: 브랜드 / 전시 / 작가 / 작품 / 방문 안내 / 언어 전환
  ↓
대표 전시: 이미지 + 전시명 + 작가 + 기간·장소 + 상세 링크
  ↓
현재·예정 전시: 운영 중인 전시가 있을 때만 표시
  ↓
선정 작품: 이미지와 간결한 작품 정보
  ↓
작가 소개 또는 검증된 소식
  ↓
방문 안내와 실제 문의 경로
  ↓
푸터: 연락처 / 운영 정보 / 실제 소셜 링크
```

가상 뷰잉룸은 서울아트만의 기능으로 유지할 수 있다. 다만 메인의 중심을 차지하기보다 작품 탐색에서 진입하는 보조 경험으로 배치하는 편이 적절하다.

## 8. 적용 우선순위와 완료 기준

### 1순위: 신뢰와 기본 동작

- 헤더 문의 버튼의 이동 대상을 수정한다.
- 문의 폼이 실제 접수인지 시연인지 사용자에게 명확하게 표시한다.
- 전시 일정, 연락처, 주소, 작품 및 작가 이력을 운영 자료와 대조한다.
- 비어 있는 링크를 정리한다.

완료 기준: 사용자가 문의·방문 경로를 끝까지 진행할 수 있고, 접수되지 않은 문의를 접수 완료라고 표시하지 않는다.

### 2순위: 메인 정보 위계

- 대표 전시 정보량을 정리한다.
- 제목·본문·캡션의 글자 크기 체계를 통일한다.
- 이미지 표시 방식과 섹션 여백을 일관되게 조정한다.

완료 기준: 데스크톱과 모바일에서 전시명, 기간, 장소, 상세 진입을 쉽게 찾고 읽을 수 있다.

### 3순위: 콘텐츠 확장과 운영

- 필요한 경우 전시·작가 상세 페이지를 추가한다.
- 새 소식은 지속적인 업데이트가 가능한 범위에서 도입한다.
- 이미지 최적화와 콘텐츠별 메타데이터를 정리한다.

완료 기준: 게시·수정 담당자가 있고, 종료된 전시와 오래된 정보가 현재 정보처럼 노출되지 않는다.

## 9. 추가 확인이 필요한 사항

다음 항목은 실제 브라우저 접근이 가능한 환경에서 별도로 관찰해야 한다.

- 원본 헤더의 스크롤 반응과 메뉴 구조
- 대표 전시 영역의 전환 방식과 자동 재생 여부
- 카드의 실제 열 수, 간격, 이미지 크롭 규칙
- 적용 폰트와 화면 폭별 글자 크기
- 모바일 메뉴, 가로 넘김, 포커스 이동
- 구독·문의·방문 경로의 실제 동작

이 항목들은 현재 문서에서 원본의 확정 사양으로 취급하지 않는다.
